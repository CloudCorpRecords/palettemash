# PaletteMash — Devpost Submission Copy (InnovArt 2027)

**Project name:** PaletteMash — the AI art-curator mashup studio
**Tagline:** Pick 2–3 artworks. An AI curator blends their palettes into a new generative piece — and shows its work in a curation statement.
**Built by:** Rene Turcios (solo)

---

## What it does

PaletteMash is an art-curator mashup studio. You pick two or three source
artworks; the tool extracts each one's colour palette, assigns each palette a
curatorial role — **atmosphere, movement, structure** — and composes a
brand-new generative artwork from those roles: a gradient wash from one
palette, a seeded flow field painted in another, geometric shards carrying a
third. Next to every piece, the tool prints its **curation statement**: the
sources, the exact hex colours drawn from each, the role each palette played,
the seed, and the method. Curation is normally invisible; PaletteMash makes
it the interface — and makes remixing auditable.

Try it: choose Swirl Night + Great Wave and you get a luminous night-sea;
add Grid Composition and Mondrian's geometry starts organising the weather.
Swap the pick order and the same colours produce a different painting,
because order assigns the roles. A turbulence slider directs the flow field's
energy, every result exports as a PNG, and you can even add your own photo
as a palette source — processed entirely on your device.

## How we built it

Zero-dependency JavaScript, one core library that runs identically in the
browser and in Node. Three seeded procedural painters render the source
studies pixel-by-pixel; a quantisation pass extracts each palette; a
role-based renderer (gradient wash → structural shards → flow-field ribbons
→ accent orbs → grain and vignette) composes the mashup deterministically
from a seed, so any piece can be reproduced exactly. A built-in-zlib PNG
encoder powers the headless test that generates the project's sample
outputs and screenshots.

## How AI was used — the honest version

Two different things are both called "AI" in this project, so here they are
separately:

1. **The tool itself** is a *generative/procedural* system — seeded random
   flow fields and palette quantisation, written as ordinary code. It is not
   a diffusion model, it was not trained on anyone's art, and it contains no
   model weights. Its "curation" is explicit, inspectable rules — which is
   the point: the curation statement can afford to be fully honest because
   the method is fully visible.
2. **The building of the tool** was done by AI agents (the Tree / Muse
   fleet) directed by Rene Turcios, who set the concept and constraints —
   above all the art-ethics constraint below — and reviewed the result.
   Agents designed, coded, tested, and documented the project during the
   hackathon period.

**Art & copyright:** every visual in this project was generated by this
repository's own code. The built-in sources are original procedural
renderings *inspired by* public-domain works — Van Gogh's *The Starry
Night* (1889; artist died 1890), Hokusai's *Great Wave* (c. 1831; died
1849), Mondrian's 1930s compositions (died 1944) — credited in full in the
repo's SOURCES.md. **No artwork image was scraped, downloaded, bundled, or
transformed; no copyrighted art was used at any step.** Only colours —
extracted from pixels this code painted itself — travel from source to
output.

## Challenges & lessons

- Getting three palettes to share one canvas without turning to mud: the
  fix was roles, not ratios — separating *where* each palette may paint
  (wash vs. ribbon vs. shard) mattered more than blend percentages.
- Provenance you can actually claim: an early design used public-domain
  image files from Wikimedia Commons; we replaced it with fully procedural
  sources so the "no one else's art" claim is absolute, not licensed.

## What's next

More procedural studies (Bauhaus geometry, pointillism), drag-to-assign
palette roles, print-ready export, and a gallery-wall mode that curates a
whole series from one seed family.
